How ORBIT keeps a large-load constraint screen auditable.

This note documents the public, non-patent-sensitive rules behind ORBIT's large-load site constraint screening. It explains evidence states, units, scenario discipline, invariant QA, economics and value-state boundaries without disclosing patent-sensitive implementation methods.

Core rule

Different physical quantities stay different.

IT load vs facility load

IT MW and facility MW are not interchangeable. Facility demand is derived from IT load using the selected PUE assumption for the scenario.

Incremental facility MW = cumulative incremental IT MW × selected PUE

Thermal, water and wastewater

Cooling is modeled in thermal units such as MWth; water and wastewater hydraulics remain in gpm. ORBIT does not subtract unlike units or infer wastewater quality from hydraulic capacity.

Evidence states

Measured facts, customer statements, modeled uncertainty and unknowns are not merged.

Fixed source-linked facts

Measured or source-linked baseline quantities are held fixed across Low / Base / High unless the source itself provides an uncertainty range.

Scenario uncertainty

Scenario variation belongs in uncertain inputs such as PUE, resource intensity, utility capacity timing, upgrade effectiveness, pricing and other modeled factors.

Unknown stays unknown

Missing chemistry or local-limit evidence remains Unknown. Hydraulic headroom alone cannot establish wastewater compliance.

Traceability

Material findings should point to evidence IDs and source locations, and state what new evidence would change the conclusion.

Constraint logic

Headroom and status are formula-linked.

Power

Utility headroom = incremental utility capacity − cumulative incremental facility demand

A separate internal-electrical screen compares the same facility-demand ramp with onsite transformer / switchgear capacity.

Cooling

Cooling load = existing peak cooling load + cumulative IT MW × heat-rejection factor
Cooling headroom = usable distribution capacity − cooling load

Water

Water demand = existing peak demand + cumulative IT MW × water-intensity factor

Wastewater hydraulics

WW demand = existing discharge + cumulative IT MW × WW-intensity factor

Quality/compliance remains a separate evidence question.

Economics

The economic case is linked to the physical constraint timeline.

The model should state what is upgraded, how much capacity it adds, when the baseline system would bind, when the upgraded system would bind, and therefore the derived deferral period.

Deferral is not avoided CAPEX. If a major expansion is deferred rather than eliminated, ORBIT values the timing difference rather than counting the full face value as savings.
Future nominal CAPEX = current CAPEX × (1 + escalation rate)^deferral years
PV future CAPEX = future nominal CAPEX / (1 + discount rate)^deferral years
Deferral benefit = current CAPEX − PV future CAPEX
3-year NPV = deferral benefit + PV(net annual operating value years 1–3) − targeted upgrade cost

Discount and escalation assumptions should be held constant across scenarios unless there is a documented reason to vary them.

G2 release gate

QA tests invariants, not the answer the analyst hoped to see.

InvariantWhat it protects against
Cumulative loads never decrease unexpectedlyPhase arithmetic errors

Wastewater quality stays Unknown without chemistry/local-limit evidenceFalse compliance inference

A scenario is allowed to change the business conclusion. The QA gate should still pass when the model is internally consistent.

Value states

Technical opportunity and realized value remain separate.

Before approval, modeled economics remain Identified / modeled. After customer approval, an initiative may carry a Forecast. Implementation and measured evidence are required before value can move toward Verified Realized in YIELD.

Boundary

Method transparency is not engineering licensure.

ORBIT is decision support. It does not replace utility confirmation, field validation, permit/compliance review, safety review, code review, licensed professional engineering or stamped design where required. Patent-sensitive implementation methods are intentionally omitted from this public note.
